Verification Status

<strong>Snapshot date: 11 November 2026, 01:25 CET.</strong> This table records the state of each requirement at the time of writing. Several modules are being implemented in parallel by other contributors, so a requirement marked <em>not started</em> below may already be in progress. The authoritative source is always the CI run (ctest + size-guard + sanitizer build) on the branch head, not this file. Update this file whenever a requirement changes state.

Status vocabulary

State Meaning
<strong>Implemented</strong> Code exists, compiles, and is exercised by an automated test
<strong>Tested on PC</strong> Portable code with an automated host-side test, no QNX needed
<strong>To validate under QNX</strong> Code exists but can only be proven on a QNX 8.0 guest under QEMU
<strong>Not started</strong> Public contract (header) defined; implementation pending

<strong>Environment facts verified on the development PC</strong> (baptiste-MS-7D18, Linux):

  • QEMU **8.2.2** installed (`qemu-system-x86_64 --version`).
  • `virtiofsd` present at `/usr/libexec/virtiofsd`.
  • QEMU supports `virtio-9p-pci` and `vhost-user-fs-pci` (`qemu-system-x86_64 -device help`).
  • **No QNX SDP installed**: `qcc` and `mkqnximage` are absent, `~/qnx800` does not exist. Cross-compiling for QNX is therefore impossible on this machine.
  • **A real QNX guest does run here**: QNX Neutrino **7.1.0** x86_64, booted by QEMU with a `virtio-9p-pci` device attached (`tests/qemu/qnx71/`). It ships no compiler, so it cannot build our driver, but it answers what QNX sees of the device — see §3.2.

What this does <strong>not</strong> do: build or run our driver. QNX 7.1 is also not QNX 8.0 — the kernel changes the specification relies on (no InterruptAttach(), capability model) are not exercised by this image. It answers the <em>device</em> question, not the <em>driver</em> question.
